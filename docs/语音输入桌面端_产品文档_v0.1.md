# 桌面端语音输入产品：产品文档 v0.1（Brainstorm 草案）

> 状态：草案，供讨论。文中带「【待决策】」的地方是需要你拍板的分叉点，我给出了倾向建议。
> 产品名暂用「Voice Layer」作代号。

---

## 1. 一句话定位

**在任何桌面应用里，按住快捷键说话，松手后，一段可直接发送的书面文字出现在光标处。**

产品的核心不是「语音转文字」，而是一层**系统级输入层**。它要做到三件事：

1. 说话的人不需要切换窗口，也不需要复制粘贴。
2. 输出的是「想表达的话」，不是「说出来的每个字」。
3. 用户能预期结果、信任结果，出错时能轻松挽回。

## 2. 为什么现在做、凭什么做

### 2.1 市场现状

AI 语音输入已经从「识别准确率」的竞争，转向「输入层体验」的竞争。几个代表产品的路线各不相同：

- **Typeless**：云端 AI 听写，强调自我纠正（说错后改口，只保留最终意思）、按应用自动调整语气，覆盖 Mac、Windows、iOS、Android 和网页。极客公园的深度体验称其「大幅降低了出错和返工的成本」，也提到免费额度为每周数千词、付费约每月 12 美元 [1]。
- **Wispr Flow**：云端听写加较重的 AI 改写，支持上下文感知格式，有 SOC 2 与 HIPAA 合规。但它曾因定期截取活动窗口截图作为 AI 上下文而引发隐私争议，也有资源占用偏高、单次录音时长受限等用户反馈（以上来自竞品厂商 Voibe 的对比文章，立场不中立，需交叉验证）[2]。
- **闪电说**：本地小模型路线，速度极快、完全免费，但中英混排、技术名词的准确率会下降 [1]。
- **Superwhisper 等**：强调本地离线、可自定义模式，面向愿意折腾的用户。
- **豆包、微信、讯飞等输入法**：以输入法形态进入，主要战场在手机，桌面端体验和「任意应用」的覆盖度各不相同。
- **macOS / Windows 系统听写**：免费、原生，但缺少书面化整理，也缺少个性化。

### 2.2 两个必须正视的威胁

极客公园文章提出了两个长期担忧，这也是我们的产品必须回答的问题 [1]：

- **系统和大厂入场**：操作系统或头部输入法做出「八十分」的系统级语音输入后，第三方工具的存在感会下降。
- **免费本地模型挤压**：用户会形成「语音转文字本身应该免费」的预期。

所以「转得准」不是壁垒。壁垒要放在别处，见 2.3。

### 2.3 我们的差异化假设

我认为值得押注的壁垒有五个，按重要性排序：

1. **插入的可靠性**。在微信、飞书、VS Code、终端、浏览器、Electron 应用、远程桌面里都能稳定上屏。这是脏活，也是真正的体验分水岭，很多竞品在长尾应用里会丢字或错位。
2. **中文场景的书面化质量**。口语到书面语的转换，在中文里比英文更难：口癖多、省略多、中英混排多、专有名词多。「整理得像你自己写的」是核心卖点。
3. **可控的改写强度**。竞品的普遍抱怨是 AI 改得太多，或者改得不够。把「保持原话 / 轻度整理 / 书面化」做成用户可感知、可一键切换的档位。
4. **上下文理解但不偷看屏幕**。通过辅助功能接口读取光标前后的文本和当前应用类型，而不是截图。这既是技术选择，也是品牌上的信任点。
5. **个人化积累**。个人词典、常用替换、写作风格、按应用设定的偏好，越用越准，形成迁移成本。

## 3. 目标用户与核心场景

### 3.1 优先用户

| 用户 | 典型场景 | 核心痛点 |
| --- | --- | --- |
| AI 重度用户、开发者 | 向 ChatGPT、Cursor、Claude 口述需求和 prompt | 想法比打字快，需要中英文术语准确 |
| 知识工作者 | 写邮件、飞书与钉钉消息、周报、文档初稿 | 口语转书面要二次整理，来回切换窗口 |
| 双语职场人 | 中英混说、即时翻译后发出 | 混排识别差，翻译要换工具 |
| 内容创作者 | 口述初稿、灵感、脚本 | 想连续说很长，不被打断 |
| 手部劳损或无障碍需求者 | 日常大量输入 | 需要稳定、可长时间使用的替代输入 |

**【待决策 1】首发人群**。我倾向「AI 重度用户加知识工作者」，且以**中文及中英混排**为主。理由是这群人付费意愿强，对速度和术语敏感，同时是 Typeless、Wispr 在中文上相对薄弱的地方。

### 3.2 关键使用场景（用来驱动设计）

- 在微信里回一条长消息，要口语但不啰嗦。
- 在 Cursor 里口述一个需求，里面夹着函数名和英文术语。
- 在邮件里先口述一团想法，希望出来是分段清晰、语气得体的正文。
- 选中一段文字，说「改得正式一点」或「翻译成英文」，原地替换。
- 在会议间隙低声说话，不想打扰旁人。

## 4. 产品原则

1. **零切换**：按下就说，松手就上屏，不打开主窗口。
2. **永不丢内容**：音频和文本在本地保留短期缓存，插入失败时用户可以一键找回。
3. **可预期**：用户总能知道「现在在听吗、处理中吗、结果去哪了」。
4. **少改写，改得准**：默认保留用户原意和语气，改写是可选的升级，不是强加。
5. **隐私默认保守**：默认不存音频、不截图、不上传不必要的上下文，并让用户看得见。
6. **轻量常驻**：内存、CPU、电量占用要明显低于竞品的反馈水平。

## 5. 核心体验设计

### 5.1 触发方式

- **按住说话（Push-to-talk）**：按住快捷键说话，松手结束。这是默认模式，最适合短句。
- **点按切换（Toggle）**：按一下开始，再按一下结束，适合长段口述。
- **锁定免手持**：按住时叠加一个修饰键，或快速双击，进入持续录音。
- **取消**：录音中按 Esc 丢弃本次内容。
- **快捷键**：允许使用单个修饰键（如 Fn、右 Option）。需要处理与系统快捷键、其他软件的冲突，并提供冲突检测。

**【待决策 2】默认快捷键与默认模式**。建议默认「按住说话」，快捷键首次引导时让用户亲手试一次。

### 5.2 录音状态指示（HUD）

一个很小的悬浮条，出现在光标附近或屏幕底部居中，包含：

- 状态（聆听、处理中、完成、出错）
- 实时音量波形，确认麦克风有效
- 当前模式和语言的小标识
- 处理超时的明确提示，不让用户盯着空白发呆

### 5.3 三种输出形态

| 形态 | 触发 | 行为 |
| --- | --- | --- |
| 听写 | 默认快捷键 | 语音转成整理后的文字，插入光标处 |
| 编辑 | 选中文字后按快捷键说指令 | 例如「更正式」「缩短」「翻译成英文」，原地替换，支持撤销 |
| 快捷短语 | 说出触发词 | 展开预设文本，如邮箱、地址、签名 |

### 5.4 改写强度档位

这是产品个性的核心控件，建议在 HUD 或菜单栏上一键切换：

1. **原样**：只做标点、断句和大小写，几乎不改词。
2. **整理**：去口癖、处理自我纠正、修正明显的语病、规范数字和英文空格。（默认）
3. **书面化**：重组语序，适合邮件、文档、汇报。
4. **自定义**：用户自写规则，例如「所有输出用简洁的技术文档风格」。

按应用设置默认档位：聊天软件默认「整理」，邮件和文档默认「书面化」，终端和代码编辑器默认「原样」。

### 5.5 出错与挽回

- **撤销上次插入**：独立快捷键，不依赖应用自己的 Cmd+Z。
- **历史记录**：保留最近若干条结果，可复制、重新插入、换一档强度重新处理。
- **失败兜底**：插入失败时，结果自动写入剪贴板，并弹出提示。
- **网络失败**：自动降级到本地模型，或排队重试，不静默丢失。

## 6. 文本处理管线

```
麦克风 → 降噪与分段 → 流式 ASR → 规整 → 上下文适配 → 改写（按档位）→ 词典与替换 → 插入
```

各环节的职责：

- **ASR**：流式识别，支持中英混说，支持热词注入。
- **规整**：去口癖和重复；识别「不对，我是说……」这类自我纠正，只保留最终意思；加标点和分段；规范数字、日期、单位；中英文之间的空格等排版。
- **上下文适配**：根据当前应用类型和光标前后文本，调整语气、列表化、术语。
- **改写**：由大语言模型按档位处理。要有保护机制，防止它「回答」用户的话（例如用户说了一个问题，模型不应当回答，而应当原样整理成问句）。
- **词典**：个人词典作为 ASR 热词，也作为后处理纠错依据。
- **延迟预算（目标）**：松手后，短句 P50 小于 1 秒、P90 小于 2 秒上屏。长段口述采用边说边处理的流式策略，缩短松手后的等待。

## 7. 「插入」的技术方案

这是最容易被低估的部分。macOS 上建议采用分层策略，按优先级回退：

1. **辅助功能接口（Accessibility）**：直接向焦点元素写入选中文本，最干净，不污染剪贴板。
2. **剪贴板加模拟粘贴**：保存原剪贴板，写入结果，发送粘贴快捷键，再恢复原剪贴板。兼容性最广，但要处理时序和剪贴板管理器。
3. **模拟键盘输入**：逐字符发送，用于前两种都失败的场景，速度慢，对长文本不友好。

必须单独处理的情况：

- **密码框与安全输入模式**：检测到时必须禁用并明确提示，这是红线。
- **Electron 与 Web 应用**：辅助功能树不完整，常需走剪贴板路径。
- **终端、远程桌面、虚拟机**：粘贴快捷键不同或不可用，需按应用适配。
- **中文输入法的组合态**：输入法正在组合时插入可能出错，需要先结束组合。
- **应用兼容表**：维护一份按应用区分的插入策略表，并支持线上热更新，因为长尾问题会持续出现。

Windows 对应方案是 UI Automation、SendInput 和剪贴板，思路相同，细节不同。

## 8. 技术架构（初步）

**【待决策 3】平台与技术栈。**

- 方案 A：**macOS 原生（Swift）先行**。系统集成最深，包体小、资源占用低，快捷键、辅助功能、音频处理都是一等公民。缺点是 Windows 要重写大部分外壳。
- 方案 B：**Tauri（Rust 加 Web UI）加平台原生模块**。核心逻辑可复用，包体比 Electron 小，插入和快捷键仍写原生模块。
- 方案 C：Electron。开发最快，但资源占用高，这恰恰是竞品被诟病的点，不建议。

我倾向 **A 或 B**。如果团队以 Web 技术栈为主，选 B；如果要把「轻量、系统级手感」当成品牌，选 A，并先只做 macOS。

模块划分：

- **客户端**：全局快捷键、音频采集与 VAD（语音活动检测）、HUD、插入引擎、上下文读取、本地缓存与历史、设置。
- **识别层（可插拔）**：云端流式 ASR 与本地模型（例如 Whisper 系、SenseVoice、Paraformer 一类）并存，按网络状况、隐私设置和语言自动路由。具体选型需要用自建的中文测试集做评测后再定。
- **整理层**：低延迟的小型 LLM，通过严格的提示词和结构化输出控制改写，并带「不要回答用户」的保护。
- **后端**：账号、订阅、额度、词典和设置同步、遥测（脱敏）。
- **评测体系**：中文口语测试集，覆盖中英混排、技术词、数字、长段口述、噪声环境，上线前后都要跑。

## 9. 隐私与信任

隐私既是合规要求，也是对 Wispr 事件的直接回应 [2]。

- 默认不保存原始音频；转写文本的保存时长由用户控制。
- 上下文只读取光标附近的文本和应用类型，不截图。读取了什么，在设置里可见、可关。
- 密码框、指定的敏感应用（如密码管理器、银行类）自动禁用，用户可维护黑名单。
- 提供「纯本地模式」：识别和整理都不出设备，质量上限较低但完全私密。
- 云端模式写清楚：音频发给谁、保留多久、是否用于训练（默认不用）。
- 企业版后续再考虑：私有部署、审计、集中配置。

## 10. 范围

### 10.1 MVP（目标：验证「每天愿意用」）

- 平台：macOS（Apple Silicon 优先）。
- 全局快捷键：按住说话、点按切换、Esc 取消。
- 中文、英文及中英混说。
- 云端流式识别加整理，三档强度（原样、整理、书面化）。
- 插入引擎：辅助功能、剪贴板两层回退，密码框保护。
- HUD、撤销上次插入、最近历史。
- 个人词典。
- 权限引导（麦克风、辅助功能、输入监控），这一步要精心设计，流失风险很高。
- 基础设置、账号与免费额度。

### 10.2 V1

- 编辑模式（选中文字加语音指令）。
- 按应用的默认强度和语气。
- 本地离线模式。
- 快捷短语。
- Windows 版本。
- 即时翻译插入。

### 10.3 V2 及以后

- 个人写作风格学习。
- 移动端（遇到系统键盘限制，需要单独评估）。
- 团队词典、企业管理功能。
- 与笔记、任务工具联动（例如口述后一键存入）。

### 10.4 明确不做（至少现阶段）

- 会议录音与纪要。这是另一类产品，会拖垮聚焦。
- 完整的录音文件转写页面。
- 语音助手式的「用声音控制电脑」。
- 自己训练基础语音模型。

## 11. 商业模式（假设）

- **免费层**：每周固定字数额度。竞品的免费额度从每周约 2,000 词到 8,000 词不等 [2]，我们的额度要有竞争力，但不宜无限，因为云端 ASR 和 LLM 有真实成本。
- **付费层**：个人订阅，价格对标竞品每月 12 到 15 美元的区间，国内市场可单独定价。
- **本地模式**：是否免费无限，需要权衡。它成本低，也能对冲「语音转文字应该免费」的心理预期，但会分流付费用户。
- **长期**：团队版和企业版。

**【待决策 4】** 目标市场是先中文区、还是全球英文用户。这直接影响定价、支付、合规和模型选型。

## 12. 成功指标

**北极星指标**：每周通过语音插入的有效字数，其中「插入后未被大幅修改」的比例（采纳率）。字数代表使用深度，采纳率代表质量。

辅助指标：

- 激活：首次成功插入的比例，权限引导完成率。
- 质量：端到端延迟（P50、P90）、插入成功率、按应用拆分的失败率、撤销率、字错误率（以内部测试集衡量）。
- 留存：7 日和 30 日留存，周活里每天使用的比例。
- 商业：免费到付费转化率，单用户日均成本与毛利。

## 13. 主要风险

| 风险 | 说明 | 应对思路 |
| --- | --- | --- |
| 系统与大厂入场 | 系统自带或头部输入法做到够好 | 押注插入可靠性、中文质量、个人化和隐私信任，而不是识别本身 |
| 权限引导流失 | 需要多项系统权限，用户易放弃 | 分步引导、解释为什么需要、检测并修复权限 |
| 插入长尾兼容 | 应用众多，持续出现边缘问题 | 应用策略表、热更新、问题上报闭环 |
| 单位成本 | 流式 ASR 加 LLM，重度用户成本高 | 本地模型兜底、小模型整理、按档位路由、额度设计 |
| 过度改写 | 模型改变原意、替用户回答问题 | 默认保守、结构化约束、原文对照、一键回退 |
| 隐私事件 | 一次争议就能毁掉信任 | 不截图、权限最小化、透明面板、第三方审计 |
| 延迟体验 | 松手后等待过长会让用户退回键盘 | 流式处理、延迟预算、超时降级 |

## 14. 想法池（待筛选）

这些是 brainstorm 中冒出来、但不一定进入首发的点子：

- **屏幕热词**：读取当前窗口里出现的人名、术语，自动加入本次识别的热词，提升专有名词准确率。
- **思路整理模式**：用户长时间无序口述，输出按「结论、理由、待办」结构化。
- **改写对照**：结果旁显示原话，一键切换「原话 / 整理后」。
- **重新处理**：对历史记录换一档强度、换一种语气重新生成。
- **低声模式**：针对小声说话优化，适合办公室。
- **多麦克风策略**：蓝牙耳机、外接麦克风、笔记本麦克风的自动选择与提示。
- **语音快捷指令**：说「发送」自动回车，说「换行」「删除上一句」。
- **按应用的个性化**：在飞书里自动用口语，在 Notion 里自动分段加标题。
- **学习用户的改动**：用户插入后又手动改了某个词，自动提示是否加入词典。

## 15. 需要你决策的问题汇总

1. 首发人群和语言：是否同意「AI 重度用户加知识工作者，中文及中英混排优先」？
2. 平台与技术栈：macOS 原生先行，还是用 Tauri 兼顾 Windows？
3. 识别路线：首发是否只做云端，本地模式放到 V1？
4. 隐私立场：是否把「不截图、可纯本地」作为明确的品牌承诺？
5. 市场与商业模式：先国内还是全球？免费额度和定价怎么设？
6. 团队与节奏：开发人力、期望的 MVP 时间点，这决定 MVP 范围要不要进一步砍。
